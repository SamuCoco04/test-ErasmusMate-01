# Figma Summary

## Design intent
Clean, modern, trustworthy academic/professional product.
Institutional core is primary.
Social layer is secondary and clearly separated.

## Role areas
- Student institutional
- Student social
- Coordinator
- Administrator

## Main navigation
Student:
- My Mobility
- Community

Coordinator:
- Dashboard
- Review Queue
- Signature Requests
- Exception Decisions
- Student Mobilities
- Procedure Management
- Deadline Management

Administrator:
- Dashboard
- User Management
- Feature Scoping
- Moderation Queue
- Reports
- Audit & Traceability

## Canonical screens
- student-dashboard.png → student institutional home
- student-submit-documents.png → official document submission flow
- coordinator-dashboard.png → coordinator operational overview
- coordinator-review-submission.png → core review/approve/reject flow
- admin-dashboard.png → governance/moderation/ops overview
- social-discover-students.png → student discovery
- social-connections.png → connections lifecycle
- social-messages.png → messaging after accepted connection
- social-map-explorer.png → map-based social discovery

## Design rules
- Institutional screens and social screens must stay separate.
- Do not mix official procedure navigation with community navigation.
- Messaging is only for accepted connections.
- Map is only for Erasmus-relevant social content.
- No route planning.
- No real-time user tracking.
- No unsafe personal location exposure.
